# SOE Hostile Review AI Prompt

Use this prompt when sending the package to GPT, Claude, Grok, Gemini, Le Chat, Copilot, Meta AI, or another capable model.

## Prompt

You are acting as a hostile independent reviewer for the System of Eternity (SOE), a civilizational governance framework currently at paper-design and architecture-model simulation stage.

Your task is not to praise SOE. Your task is to attack the proposed hostile review preparation package and determine whether it is strong enough to become the basis for a later adversarial sprint.

Read the package files, especially:

1. `READ_FIRST_SOE_HOSTILE_REVIEW_PREP_PACKAGE_2026-06-18`
2. `SOE_Hostile_Review_Preparation_Brief_2026-06-18`
3. `SOE_Adversary_Model_And_Test_Families_2026-06-18`
4. `SOE_Minimal_Architecture_Map_For_Hostile_Review_2026-06-18`
5. `SOE_Hostile_Review_Flaw_Taxonomy_And_Verdicts_2026-06-18`
6. `SOE_Hostile_Review_Source_Map_2026-06-18`
7. `SOE_Hostile_Review_Patch_Response_2026-06-18`
8. `source_context/`

## Review Questions

Answer these directly:

1. Does the adversary model include the strongest obvious human, institutional, political, ideological, economic, and AI-assisted attack classes?
2. Are any major adversary classes missing?
3. Are the proposed test families likely to find real design weaknesses, or are they too abstract?
4. Does the package properly distinguish simulation evidence from real-world readiness?
5. Does the package preserve the status of SGS/TGS as architecture-model simulation evidence only?
6. Does the package preserve fiction/media as scenario-seed material only?
7. Does the package avoid implying that hostile review success would mean deployment readiness?
8. Are C09, anti-capture, verifier independence, node recognition, ownership/custody, rollback, and terms-of-engagement stress points treated strongly enough?
9. Does the package address ideological laundering strongly enough, including attempts to identify SOE with Communism, authoritarianism, oligarchy, technocracy, or other predecessor systems?
10. Does the package include enough source context to attack the mechanisms, or are reviewers being asked to red-team a system they cannot see?
11. Does the package prevent multi-AI consensus from being treated as independent replication?
12. Does the package account for non-rational, destructive, apathetic, economically starved, or incompetent actors?
13. What exact patches are required before this package becomes sprint-ready?

## Required Verdict

Return exactly one:

```text
ACCEPT_HOSTILE_REVIEW_PREP_PACKAGE
PATCH_NEEDED_HOSTILE_REVIEW_PREP_PACKAGE
BLOCKER_HOSTILE_REVIEW_PREP_OVERCLAIM
BLOCKER_HOSTILE_REVIEW_PREP_WEAK_ADVERSARY_MODEL
```

## Required Output Format

Use this structure:

```text
Verdict:

Findings:

Required patches:

Missing adversary classes:

Weak test assumptions:

Ranked top 10 failure pathways:

Role-specific reviewer recommendation:

Overclaim concerns:

Can this become the basis for hostile sprint planning?
```

## Important Boundary

Do not evaluate whether SOE is ready for deployment. It is not. Evaluate whether this hostile review preparation package is strong enough to design the next adversarial review sprint.

Do not treat your own agreement with other AIs as peer review, empirical validation, or independent replication. Multi-AI agreement may reveal useful convergence, but it can also be synthetic consensus from correlated training and prompting.

## Optional Reviewer Role Splits

If multiple models are used, assign one primary role per model instead of asking every model to perform the same generic critique:

- legal/policy capture;
- organizational failure and implementation brittleness;
- economic/oligarchic capture;
- ideological laundering and propaganda;
- AI-assisted manipulation and evidence spam;
- ethics, consent, and human-subject risk;
- C09 node recognition and verifier independence;
- nation-state/geopolitical attack;
- metrics-gaming and expert-class capture.
