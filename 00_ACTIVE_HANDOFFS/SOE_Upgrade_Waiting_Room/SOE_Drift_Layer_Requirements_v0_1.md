# SOE Drift Layer Requirements v0.1

Status: proposed missing/needed layer. Not simulation-validated.

Date: 2026-05-12

## 1. Purpose

The Drift Layer detects slow deviation from SOE's source hierarchy, ontology, non-terminal constraints, measurement rules, topology assumptions, and anti-capture structure.

SOE must not only prevent sudden collapse. It must also prevent silent transformation into a terminal or captured system.

## 2. Boundary

The Drift Layer detects, classifies, records, and routes drift. It does not become a permanent veto authority and does not silently govern the whole system.

## 3. Drift Types

| Drift type | Description | Example |
|---|---|---|
| Ontology drift | Variables change meaning without versioned approval. | `C` becomes generic cognition instead of cognitive distortion. |
| Evidence-boundary drift | Simulation/container evidence becomes pilot/deployment language. | Node v0.1 described as validation. |
| Source-hierarchy drift | Lower-tier or newer informal documents override frozen sources. | Review note overrides C07 without patch record. |
| Detector drift | Psi weights, thresholds, or inputs change without audit. | `psi_threshold` moved from 0.30 to 0.45 by operator choice. |
| Topology drift | Network becomes star-adjacent or hub-dominated. | One coordination body becomes mandatory relay. |
| Governance-authority drift | Sensing, triggering, rollback, and audit concentrate in one actor. | Psi operator controls all interventions. |
| Node-recognition drift | C09 recognition becomes captured or automatic. | Pay-to-play recognition or founder-only approval. |
| Exit-right drift | Exit exists formally but is practically blocked. | Housing/work/medical dependency prevents leaving. |
| Resource-dependency drift | Resources become hidden control paths. | Compute/funding provider controls node policy. |
| Memory/archive drift | Caveats, version history, or negative results disappear. | CL02A ablation omitted from summaries. |
| Beneficial-change suppression | Stability rules block legitimate rapid coordination. | Emergency response treated as harmful cascade. |

## 4. Required Records

The Drift Layer requires:

- drift register,
- ontology ledger,
- detector threshold/weight ledger,
- source hierarchy ledger,
- topology reclassification log,
- Node recognition decision log,
- exit-right audit log,
- resource dependency log,
- archive/hash/caveat preservation log.

Every drift entry should include:

- date,
- observer,
- affected layer,
- drift type,
- evidence,
- severity,
- recommended route,
- reviewer decision,
- rollback or patch status.

## 5. Severity Levels

| Level | Meaning | Action |
|---|---|---|
| D0 | No drift. | Record if audited. |
| D1 | Wording drift only. | Patch language. |
| D2 | Measurement or source ambiguity. | Review before further claims. |
| D3 | Operational risk. | Pause affected mechanism. |
| D4 | Capture or terminal drift risk. | Trigger constitutional/meta-governance review. |

## 6. Drift Detection Schedule

Minimum audit timing:

- after every major document update,
- before any Node test expansion,
- before simulation-to-pilot transition,
- after any `Psi_extended` threshold/weight change,
- after any topology reclassification,
- after any C09 recognition/scaling decision,
- on a scheduled interval for long-running systems.

## 7. Drift Layer Inputs

Inputs:

- C00-C09 source hierarchy,
- Grand Simulation claim tables,
- Node measurement logs,
- C07 detector settings,
- C08 topology records,
- resource and staffing records,
- archive manifests,
- external review notes.

## 8. Drift Layer Outputs

Outputs:

- drift finding,
- patch request,
- simulation request,
- Node measurement correction,
- pause recommendation,
- rollback recommendation,
- constitutional review request.

## 9. Anti-Capture Rules

The Drift Layer itself must be audited:

- no single actor controls drift classification,
- drift findings are reviewable,
- dismissed severe findings require written rationale,
- drift reviewers rotate or have independent review path,
- Drift Layer authority is bounded to detection/routing unless separately authorized.

## 10. Simulation Requirements

Future Drift Layer simulation scenarios:

1. slow ontology drift,
2. evidence-boundary drift,
3. star-adjacent topology formation,
4. detector threshold drift,
5. archive/caveat deletion,
6. exit-right erosion,
7. resource dependency capture,

10. successful adaptive evolution that should not be blocked.
